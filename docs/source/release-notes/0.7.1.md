# Moro 0.7.1 — Release Notes

Moro 0.7.1 is a maintenance release that improves the reliability of
numerical inverse kinematics using Levenberg–Marquardt (LM).
It fixes premature termination while retaining the existing public API
and solver defaults.

## Highlights

### More reliable LM damping adaptation

Previously, LM could reject several trial joint updates while increasing
its damping parameter, and these rejected trials would also accumulate
as stagnation. A reachable target could therefore be reported as
stagnated just before a smaller, properly damped update would succeed.

Moro now distinguishes **rejected damping-adjustment trials** from
**accepted steps that make insufficient progress** in both
`solve_position_ik()` and `solve_pose_ik()`.

Rejected trials still count toward `max_iter` and the reported
`iterations` value. Consecutive rejections remain bounded, and a
negligible effective step caused by joint limits can still trigger
step-stagnation termination. This change does not remove the safeguards
against unreachable or constrained targets.

### Regression coverage

The regression suite now includes the reported RR and RRR manipulators
whose position-IK solves could stop prematurely with the default
`stagnation_iterations=5`. These examples now converge with the
default LM settings.

Additional tests cover physically equivalent metre- and
millimetre-scale models, limits on revolute and prismatic joints,
unreachable targets, near-singular configurations, deterministic
random initialization, full-pose IK, and sequential position IK.

## Example: position IK

The following example previously could terminate after five rejected
LM trials, despite a reachable Cartesian target:

```python
from moro.core import Robot
from moro.abc import q1, q2
from moro.inverse_kinematics import solve_position_ik

robot = Robot((200, 0, 0, q1), (200, 0, 0, q2))

solution = solve_position_ik(
    robot,
    [200, 200, 0],
    q0=[0.1, 0.1],
)

print(solution.converged)  # True
print(solution.error)
```

The equivalent geometric model may also be expressed in metres rather
than millimetres. However, absolute position tolerances must be scaled
consistently with the linear units used by the robot model and target.

## Compatibility and limitations

This patch does **not** change public function signatures, result
structures, method names, or defaults. The default LM options remain
`damping=1.0` and `stagnation_iterations=5`.

Numerical results can differ from 0.7.0: a solve that previously stopped
due to premature stagnation may now converge, and its iteration count
may change.

**This is not a guarantee of convergence from every initial guess or
numerical invariance under unit conversions.** The same numerical
`damping` value can lead to different update sequences when geometry
is represented in metres rather than millimetres. For position IK,
`tol` and `error_change_tol` are absolute thresholds expressed in
the model's linear units; adjust them when converting units. General
unit-aware damping normalization, especially for mixed
revolute/prismatic and weighted full-pose IK, remains outside the scope
of this patch.
